# DWM3001CDK — macOS Zephyr development starter

One-command **developer setup** for Qorvo **DWM3001CDK** boards on **Apple Silicon macOS**. It installs Python, west, Zephyr, the ARM compiler and the tools needed to build C applications from VS Code. **The installer never flashes, erases, resets or connects to the board.**

The kit also includes a small Zephyr application (`dwm3001-app/`) that builds for the nRF52833 and blinks the D9 user LED. It does **not** initialize the DW3110 UWB transceiver; UWB ranging needs additional driver/SDK work.

## 1. Requirements

- **Apple Silicon Mac (arm64)**. Current Zephyr getting-started instructions do not support Intel (x86-64) macOS.
- **Homebrew** already installed: <https://brew.sh/>. If necessary, install Xcode Command Line Tools (`xcode-select --install`) first.
- Internet access and enough disk space for a sizable Zephyr checkout and SDK.
- A path without spaces for the Zephyr workspace and your application source/build path. For example, `~/zephyrproject` and `~/Projects/dodgit`.
- USB cable and DWM3001CDK only when you choose to test on hardware later — **not needed for setup**.

## 2. One-command installation

From this repository root:

```bash
bash ./setup-macos.sh
```

What it does, in order:

1. Checks macOS and Apple Silicon architecture.
2. Installs build utilities via Homebrew (`git`, `cmake`, `ninja`, `gperf`, `ccache`, `qemu`, `dtc`, `libmagic`, `wget`, `openocd`, `uv`).
3. Installs VS Code and SEGGER J-Link **host software** if absent; this installs tools but **does not touch your hardware**.
4. Installs **Python 3.12** using `uv` and creates/reuses `~/zephyrproject/.venv`. This avoids relying on a potentially broken Homebrew/Conda Python environment.
5. Installs `pip` and `west` in that virtual environment.
6. Initializes a Zephyr workspace at `~/zephyrproject` if one does not exist. **New workspaces start from the pinned Zephyr `v4.4.0` tag** (latest stable when this kit was prepared). An **existing checkout is preserved**, including its current Zephyr revision.
7. Downloads/upgrades manifest-controlled Zephyr modules with `west update`.
8. Installs Zephyr's own Python requirements and exports its CMake package.
9. Installs **only the `arm-zephyr-eabi` Zephyr SDK toolchain**, checks DWM3001CDK board support and **compiles** Zephyr's Blinky sample as a no-hardware smoke test.

The script can be rerun after an interrupted installation. It doesn't delete your source repository or a preexisting Zephyr checkout. Rerunning `west update` may synchronize *Zephyr modules* to manifest versions, so don't keep local modifications inside Zephyr-managed module trees.

**Notes:** Homebrew and GUI/cask installers can request permissions. Installing J-Link software may involve acceptance of SEGGER's license. On first hardware connection, SEGGER J-Link software may prompt/update the probe firmware independently of this installer.

### Optional environment variables

```bash
# Change the workspace location (must not contain spaces)
ZEPHYR_WORKSPACE="$HOME/zephyrproject" bash ./setup-macos.sh

# Choose the Zephyr revision for a NEW workspace only
ZEPHYR_REVISION=v4.4.0 bash ./setup-macos.sh

# Skip optional VS Code / J-Link host-tool installation
INSTALL_GUI_TOOLS=0 bash ./setup-macos.sh

# Skip the final compile-only Blinky validation
BUILD_TEST=0 bash ./setup-macos.sh
```

## 3. Start a VS Code firmware project

The included app is a working example with these files:

```text
dwm3001-app/
├── CMakeLists.txt
├── prj.conf
└── src/
    └── main.c
.vscode/
├── c_cpp_properties.json
└── extensions.json
```

To begin a new project, copy the `dwm3001-app` folder within your own Git repo and edit its `src/main.c`. In VS Code, open the **repository root** (the directory containing `.vscode/` and `dwm3001-app/`). Install the recommended **C/C++** extension when prompted.

The `.vscode/c_cpp_properties.json` uses `${workspaceFolder}/dwm3001-app/build/compile_commands.json`, which is generated by the build. Red underlines on `<zephyr/...>` includes may remain until the first successful build. If IntelliSense doesn't refresh, run **C/C++: Reset IntelliSense Database**, then **Developer: Reload Window**.

## 4. Build from VS Code Terminal (no hardware needed)

```bash
source ~/zephyrproject/.venv/bin/activate

# Run from this repo's root (adjust if your project is elsewhere)
APP_DIR="$(pwd)/dwm3001-app"

cd ~/zephyrproject
west build -p always \
  -b decawave_dwm3001cdk \
  "$APP_DIR" \
  -d "$APP_DIR/build" \
  -- -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

Expected files:

- `dwm3001-app/build/zephyr/zephyr.hex` — ready-to-program firmware image.
- `dwm3001-app/build/compile_commands.json` — VS Code IntelliSense configuration database.

Run `west boards | grep dwm3001` and `west sdk list` to inspect your installed support.

**If you rename/move the project after a build:** remove only its generated build directory (`rm -rf "$APP_DIR/build"`) and rebuild. CMake caches the original absolute path.

## 5. Future flashing — manual only, never run by setup

The installer does **not** call `west flash` or J-Flash. When you intentionally decide to program a DWM3001CDK later:

1. Preserve any original application firmware and relevant UICR configuration you need, before replacing anything.
2. Connect the board using its **J-Link** micro-USB port. Verify the SEGGER CLI is present using `command -v JLinkExe`.
3. Flash the already-built image **manually** with:

```bash
source ~/zephyrproject/.venv/bin/activate
APP_DIR="$(pwd)/dwm3001-app"   # run this in your repository root
west flash -d "$APP_DIR/build" --runner jlink
```

Alternatively, use SEGGER J-Flash/J-Flash Lite and select the output `.hex`, device `NRF52833_xxAA`, and SWD. **Never use a recover/unlock or mass-erase command as a substitute for an ordinary flash**; unlocking protected chips can erase user firmware/configuration.

## 6. Common problems

| Symptom | Resolution |
| --- | --- |
| `ensurepip` errors or `platform.mac_ver()` empty | The script uses `uv`-managed Python 3.12 rather than Homebrew Python. |
| Terminal has `(base)` from Conda | Use the Zephyr virtual environment explicitly: `source ~/zephyrproject/.venv/bin/activate`. |
| `west: command not found` | Activate the virtual environment first. |
| `File not found: /.../Toy` for a path such as `Toy Design` | Use application and build paths **without spaces**. |
| CMake complains about an old source directory after a rename | Delete only your app's generated `build/` directory and rebuild. |
| VS Code cannot find `<zephyr/kernel.h>` | Build with `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`, then reload VS Code. |
| `JLinkExe` not found later | Install SEGGER J-Link software from <https://www.segger.com/downloads/jlink/>. |
| Board not found | Check the active Zephyr version and `west boards | grep dwm3001`. |
